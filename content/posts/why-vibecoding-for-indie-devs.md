## 痛点才是最好的需求池

做独立工具多年，我最大的体会是：**只要你不是那个每天都会痛苦使用它的人，你就很容易做出浮夸而无用的功能。**

以往做一款 App，流程往往冗长：画原型、写交互设计规范、搭框架、查文档、改 Bug……耗费数周乃至数月后，热情早已被琐碎的工程配置消磨殆尽。更糟糕的是，很多功能做出来后，自己一个月也用不上一次。

直到 Vibecoding（氛围感编程 / 意图驱动编程）成为我的主力工作方式，一切彻底变了。

> [!NOTE]
> **什么是 Vibecoding？**
> Vibecoding 并不是盲目让 AI 生成一堆不可控的垃圾代码，而是由开发者掌舵审美、架构理念与核心心流，把具象的代码实现与调试交给高智商大模型伙伴，实现端到端的极速现实交付。

## 一人工坊的自造法则

在 JohnnyBoyStudio，我给自己立下了三条铁律：

### 1. 绝不为虚构的用户画像写代码
我的每一个工具（例如摄影选片工作台 **QuickPick**、生活流助理 **assistan01**、跨端摆渡 **Ferry**），最初的立项原因都只有一个——**我自己每天都在为某个环节暴躁。**
如果我自己都懒得用，那它就不该存在。

### 2. 交互要利落，拒绝臃肿
好的工具像一把锋利的瑞士军刀，而不是堆砌了二十种塑料配件的工具箱。
- 启动必须是毫秒级；
- 操作要有清晰的触觉与快捷键反馈；
- 绝不在关键流程中打断用户的注意力。

### 3. 本地优先，数据尊重
用户的素材、照片和隐私是神圣的。原片绝不上传云端，所有图像计算与本地 SQLite 记录都留在用户的 Mac 本地芯片上。

```swift
// 一个好的原生体验，核心在于把繁琐的等待剥离
func renderPhotoCanvas(rawPath: URL) async throws -> DecodedImage {
    // 毫秒级原生解码，100% 只读安全
    let safeBuffer = try await LocalDecoders.loadReadOnly(rawPath)
    return safeBuffer.renderToMetalSurface()
}
```

## Vibecoding 是如何改变开发心流的？

在以前，写一个复杂的 Metal 构图线或 Rust 多线程扫描，需要反复阅读数十页的底层 API 手册与排查内存对齐。

而在现代 Vibecoding 下：
1. **表达意图**：我明确告诉 AI 结对伙伴我想要的视觉质感、构图比例（黄金螺旋与三分线）以及零拷贝性能要求；
2. **极速迭代**：大模型生成结构骨架，我来做审美验收与边界压力测试；
3. **沉浸心流**：思维不再卡在语法分号和配置报错里，而是一直保持在**产品构想**与**用户体验**的高维层级。

> [!TIP]
> 当你在构建自用工具时，不要害怕它太小众。只要你在某个垂直场景下把它做到了极度顺手，这世界上一定有一群和你一样挑剔的同类在等待它。
